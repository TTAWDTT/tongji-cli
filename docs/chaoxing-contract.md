# 学习通接口约定

本模块遵循仓库现有适配方式，不引入独立客户端框架：命令在 cli.py 注册，认证交给 auth.py，学习通请求和解析集中在 chaoxing.py，汇总交给 schedule.py，终端显示交给 display.py。

## 对齐依据

- canvas/api.py 的 request：验证来源、HTTP 状态和响应类型，再解析数据。
- media/courses.py 的 courses/course_page：标识、页面结构、空结果和列表完整性需要明确证据，不能把解析失败当成零项。
- common.py 的 QueryUnavailable/failure 与 display.py：使用既有状态和错误出口；聚合失败时保留成功来源。

## 输入和请求

课程选择必须唯一，空字符串不代表全部课程。同名多班使用课程 ID 与班级 ID 组成的复合 ID。服务端课程标识必须为单个数字值；作业必须具有稳定 workId，其链接中出现的课程、班级 ID 必须与所选对象一致。

只执行 GET。每次请求 20 秒超时，不自动重试。只接受超星子域和默认 HTTPS 端口，HTTP 入口升级为 HTTPS；每一跳验证目标，最多六次请求。拒绝站外跳转、异常端口、缺失跳转地址、非 HTML 响应。底层请求异常转换为不含底层 URL、Cookie 和签名的错误说明。

## 输出和失败

课程沿用标准 id/title；作业沿用 id/title/course/submitted/due/source，附带班级、官方状态和时间原文。submitted 只取 true、false、null；无法核对的状态不推断为未交。due 仅在年份、日期、时间都能核实时输出上海时区 ISO 时间，否则 null，原始作答时间保留在 due_as_listed。

正常空结果需要页面明确的无课程或无作业标记。标识缺失、重复、页面无法识别、发现未处理的下一页时报告未核实，不能宣称读取完整目录。当前不自动遍历分页；遇到新分页布局应增加相应真实页面样例、分页逻辑和完整性测试后再支持。

作业详情失败保留列表中已确认的名称、提交状态和链接，添加 detail_status=unverified，同时在 errors 中记录受影响作业。结果返回 partial。单门课程失败不阻止其他课程查询。周汇总保留成功来源，日期未知的作业单列；部分成功返回非零退出码，调用者必须同时读取 JSON。

## 维护与验证

维护时先确认官方页面结构，再修改本模块；复用已有 QueryUnavailable 和显示机制。新增布局须同时提供脱敏样例及覆盖其失败边界的测试，不把个人课程 HTML、登录资料或带签名的真实作业 URL 提交进 Git。

测试至少覆盖响应类型、超时、站外跳转、无年份日期、无效日期、课程歧义、标识错误、跨班链接、分页信号、详情失败保留列表和部分成功汇总。网页变动可能要求重新适配；离线测试不能替代真实登录、目录、作业和周汇总验证。

默认 login/status/today/week 的来源范围统一为教务与 Canvas。学习通需单独认证，并以 --include-chaoxing 显式加入 today/week。作业时间仅从以标签开头的结构化时间字段提取，不扫描正文中其他活动日期；百分号编码的详情链接原样保留。
